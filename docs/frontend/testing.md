# Mission 05 frontend and integration testing

## Test layers

- Vitest unit tests cover exact 30-feature validation, non-finite/extra/target rejection, bounded
  batch parsing and batch result sorting/filtering, formatting, risk labels, empty/offline states,
  log-odds chart labels, and API error mapping. Unit tests stub network responses; production
  transport has no mock fallback.
- Playwright browser tests use Playwright's pinned Chromium build and the real local API. They cover API
  health, responsive navigation, single prediction plus local explanation, batch prediction, CSV
  upload/analysis/result/deletion, prioritization, anomaly scoring, investigation create/update/note,
  and the global validation SHAP page. An axe-core test checks WCAG 2.1 A/AA and best-practice rules
  across nine primary routes at 1440 px and 390 px.
- Python regression uses the isolated Mission 01–04 check script. The frontend HTTP smoke checks
  local API health/readiness and frontend HTTP response before browser workflows.

## Commands

From repository root:

```powershell
.\scripts\run-frontend-checks.ps1
.\scripts\run-checks.ps1 -PythonPath '.venv-isolated\Scripts\python.exe'
.\scripts\smoke-frontend.ps1 -PythonPath '.venv-isolated\Scripts\python.exe'
```

`run-frontend-checks.ps1` runs typecheck, ESLint, Vitest, and a production build in sequence.
`smoke-frontend.ps1 -SkipBrowser` performs only HTTP health/readiness checks. Install the matching
Playwright Chromium build once with `npx playwright install chromium` from `frontend/`; the browser
suite also requires a ready API on loopback and frontend dependencies.

Mission 05 final run: 5 Vitest files / 16 tests passed; 8 Playwright tests passed (7 workflow tests
and one axe scan), with zero WCAG 2.1 A/AA or best-practice violations in the scanned routes.

## Test data

Browser workflows explicitly send zero-filled synthetic vectors and a one-row synthetic feature
CSV. The analysis is deleted after its result is read. Investigation API has no delete endpoint;
the browser test leaves one case named `Mission 05 E2E synthetic review` with an explicitly
synthetic note in the local database. These test writes are never generated by the product at
startup and must not be presented as real history. Local API history may also receive explicit
synthetic prediction rows from browser tests. The final validation used throwaway Mission 05 API
databases; these do not replace or alter the existing Mission 04 database.

Never use the consumed Mission 02 final-test observations for frontend tests, demos, tuning, or
independent model claims.
